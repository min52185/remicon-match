이 문서 하나만 읽으면 시작할 수 있게 썼습니다. **Git 이나 Next.js 를 몰라도 됩니다.**

- 사이트: <https://remicon-match-iota.vercel.app>
- 저장소: <https://github.com/min52185/remicon-match>
- 무엇: 건설 현장이 레미콘을 주문하면, 공장이 배차하고, 기사가 배송하는
  과정을 한 화면에서 보는 시스템. 경희대 시스템설계 조별과제입니다.

# 0. 받아야 할 것 — 세 가지

| 받는 것 | 어디서 | 없으면 |
| --- | --- | --- |
| **코드** | ZIP 파일 또는 GitHub | 시작 못 함 |
| **키 3줄** (`.env.local`) | 채팅방으로 따로 받습니다 | 돌아가긴 합니다 (아래 2-3) |
| **시연 계정** | 채팅방 | 로그인 못 함 |

> ⚠️ **키는 ZIP 안에 없습니다.** 일부러 뺐습니다. 공개 저장소라 키가 코드에
> 섞이면 아무나 DB 에 접근할 수 있습니다. 채팅방으로 따로 받으세요.

# 1. 코드 받는 법 — 둘 중 하나

## 1-1. GitHub (권장)

고친 것을 다시 올릴 수 있습니다. **여러 명이 같이 고칠 거면 이 방법입니다.**

1. GitHub 계정을 만들고 아이디를 저장소 주인에게 알립니다
2. 주인이 초대하면 메일이 옵니다 → **수락**
3. 터미널에서

```bash
git clone https://github.com/min52185/remicon-match.git
cd remicon-match
npm install
```

> 공개 저장소라 초대 없이도 `git clone` 은 됩니다. 다만 **올리지는(push) 못합니다.**
> 보기만 할 거면 초대가 필요 없고, 고쳐서 반영할 거면 초대가 필요합니다.

## 1-2. ZIP 파일

한 사람이 혼자 고칠 때만 씁니다. **고친 것을 합치기가 어렵습니다.**

1. 받은 ZIP 을 풉니다
2. 푼 폴더에서 터미널을 엽니다
   - 윈도우: 폴더 빈 곳에서 마우스 오른쪽 → **터미널에서 열기**
3. `npm install`

# 2. 처음 한 번 세팅 (30분)

## 2-1. Node.js 설치

<https://nodejs.org> 에서 **LTS** 버전. 선택지는 전부 기본값.

설치 후 터미널에서 확인:

```bash
node -v
```

`v20...` 처럼 나오면 됩니다.

## 2-2. 패키지 설치

프로젝트 폴더에서:

```bash
npm install
```

3~5분 걸립니다. `node_modules` 폴더가 생깁니다. **이 폴더는 건드리지 않습니다.**

## 2-3. 키 넣기

채팅방에서 받은 내용을 그대로 **`.env.local`** 이라는 파일로 만들어
**프로젝트 맨 위 폴더**(`package.json` 이 있는 곳)에 둡니다.

> **키가 아직 없어도 일단 돌아갑니다.** 로그인 없는 **시연 모드**가 되고,
> 지도는 대체 지도로, 이동시간은 직선거리 근사로 바뀝니다.
> 화면 위쪽에 지금 어느 쪽인지 표시됩니다. 화면 모양을 고치는 작업이라면
> 키 없이도 충분합니다.

## 2-4. 실행

```bash
npm run dev
```

<http://localhost:3000> 이 열리면 성공입니다. **끌 때는 터미널에서 Ctrl+C.**

키 없이 시연 모드로 보고 싶으면:

```bash
npm run dev:demo
```

# 3. 어디에 무엇이 있나

```
app/site/        현장(건설사) 화면 — 주문·추적·납품서·현장 등록
app/plant/       레미콘사 화면 — 출하 현황·배차·공장 등록
app/driver/      기사 화면 — 내 배송·GPS·사진
app/api/         서버 — 카카오 길찾기·기상청·AI 배분·주소 검색

lib/rules.ts     시방·KS 규칙 — 90분, 25℃, 6m3 같은 숫자는 전부 여기
lib/ai/          배분 최적화·지연 예측·긴급 매칭
lib/store/       저장소 — local(브라우저) / remote(Supabase)
lib/services/    외부 API·시연 시계·사진
components/      화면 공용 부품

tests/           자동 테스트
supabase/        DB 구조(migrations)
docs/            시연 매뉴얼·진행 보고서·협업 가이드·이 문서
```

**화면을 고치려면** `app/` 안에서 찾습니다. 파일 이름이 `page.tsx` 인 것이
실제 한 화면입니다.

# 4. 자주 하는 편집 세 가지

## 4-1. 화면의 글자 바꾸기

해당 `page.tsx` 에서 따옴표 안의 한글을 찾아 고치면 됩니다.
찾기가 어려우면 터미널에서:

```bash
grep -rn "바꾸고 싶은 문구" app components
```

파일 이름과 줄 번호가 나옵니다.

## 4-2. 색·글꼴 바꾸기

`app/globals.css` 위쪽에 색이 이름으로 정리돼 있습니다. 거기만 고치면
전체 화면에 반영됩니다. 화면마다 색을 직접 쓰지 마세요.

## 4-3. 시방 수치 바꾸기

**`lib/rules.ts` 에서만 고칩니다.** 90분·25℃·6m3 같은 값이 전부 상수로
모여 있습니다. 화면 코드에 숫자를 직접 쓰면, 나중에 기준이 바뀔 때
어디를 고쳐야 할지 아무도 모르게 됩니다.

확실하지 않은 값에는 `// [가정]` 주석이 붙어 있습니다. 그대로 두세요.

# 5. 지켜야 할 규칙

| 규칙 | 왜 |
| --- | --- |
| **`.env.local` 을 커밋하지 않는다** | 공개 저장소입니다. 올라가면 키를 새로 발급해야 합니다 |
| **`SUPABASE_SERVICE_ROLE_KEY` 를 쓰지 않는다** | 권한 검사를 통째로 무시하는 키입니다 |
| **시방 수치는 `lib/rules.ts` 에만** | 기준이 바뀔 때 한 군데만 고치게 |
| **새 DB 테이블에는 RLS** | 안 걸면 남의 회사 자료가 보입니다 |
| **개인 이메일·전화를 코드에 쓰지 않는다** | 공개 저장소입니다 |
| **얼굴 사진은 개인정보** | 동의 체크 없이 올리지 않습니다. 비공개 버킷 + 10분짜리 링크로만 봅니다 |
| **기능을 만들면 테스트도** | `tests/` 에 같이 넣습니다 |

자세한 것은 `CLAUDE.md` 에 있습니다.

# 6. 고친 뒤 — 올리기 전에

```bash
npm test
```

**통과해야 올립니다.** 실패하면 무언가를 망가뜨린 것입니다.

> `npm run build` 를 돌릴 때는 **개발 서버를 먼저 끄세요**(Ctrl+C).
> 둘 다 `.next` 폴더를 써서 켜 둔 채 빌드하면 캐시가 깨집니다.

## GitHub 로 올리기

```bash
git pull
git add .
git commit -m "무엇을 왜 바꿨는지"
git push
```

올리면 GitHub 가 **타입 검사 · 테스트 · 빌드**를 자동으로 돌립니다.
저장소 **Actions** 탭에서 봅니다.

| 표시 | 뜻 |
| --- | --- |
| 노란 점 | 검사 중 (1~2분) |
| 초록 체크 | 통과. 배포까지 자동입니다 |
| 빨간 X | **깨졌습니다.** 눌러서 어디가 빨간지 보고 고칩니다 |

> 빨간 X 가 뜨면 **배포본도 그 상태로 나갑니다.** 발표 전에 빨간 X 가
> 있으면 안 됩니다.

## ZIP 으로 받았다면

고친 폴더를 다시 압축해 돌려보냅니다. 단 **`node_modules` 와 `.next` 는
빼고** 보내세요 (수백 MB 입니다). 무엇을 고쳤는지 메모를 같이 주세요.

# 7. 막혔을 때

| 증상 | 해결 |
| --- | --- |
| `npm run dev` 가 `Cannot find module` | `rm -rf .next` 후 다시 실행 |
| `npm install` 이 실패 | Node 버전 확인 (`node -v`, 20 이상) |
| 포트가 이미 쓰인다 | 다른 터미널에서 서버가 켜져 있습니다. Ctrl+C |
| 지도가 안 뜬다 | 키가 없거나 틀립니다. 시연 모드면 정상입니다 |
| 로그인이 안 된다 | Supabase 키 확인. 계정은 채팅방에서 받습니다 |
| `git push` 가 거부됨 | `git pull` 먼저 하고 다시 `git push` |
| 충돌(conflict) | 혼자 풀지 말고 Git 아는 사람을 부르세요 |
