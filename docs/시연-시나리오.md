# 레미go 시연 시나리오

발표용 대본입니다. **약 9분** 분량이고, 장면마다 무엇을 누르고 무엇을 말할지 적었습니다.
여기 적힌 숫자와 반응은 전부 실제로 확인한 것입니다 — 상상해서 쓴 값이 없습니다.

---

## 0. 발표 30분 전 — 준비

### 0-1. 기기와 계정

| 기기 | 계정 | 열어 둘 화면 | 비고 |
| --- | --- | --- | --- |
| **노트북** (화면 공유) | 현장 | `/site/order` | 주 화면. 프로젝터에 연결 |
| **휴대폰 A** | 레미콘사 | `/plant/orders` | 실시간 도착을 보여줄 기기 |
| **휴대폰 B** | 기사 | `/driver` | 없으면 노트북 시크릿 창으로 대체 |

- 주소: <https://remicon-match-iota.vercel.app>
- 레미콘사와 기사는 **같은 회사(가온레미콘)** 여야 합니다.
- 기사는 미리 **내 차량 → 1호차**를 맡아 둡니다. 안 하면 배송이 안 보입니다.

### 0-2. 데이터 비우기

지난 리허설 데이터가 남아 있으면 화면이 지저분합니다.

Supabase → **Table Editor** → 아래 **순서대로** 전체 행 삭제:

1. `truck_locations`
2. `deliveries`
3. `plan_items`
4. `orders`
5. `allocation_plans`

> 배송이 주문을 참조하므로 순서를 지켜야 합니다. 거꾸로 하면 외래키 오류가 납니다.

그다음 `plant_status` 의 `가온레미콘 동탄공장` 행을 `available_trucks = 8`, `available_volume = 240`
으로 되돌립니다(리허설 중 줄어듭니다).

### 0-3. 마지막 점검

각 기기에서 `/setup` 을 열어 **1·2번이 초록**인지 확인합니다. 빨간색이면 지도나 길찾기가 안 됩니다.

### 0-4. 화면 설정

- 노트북 브라우저 **확대 125~150%** (뒷자리에서 보이게)
- 알림·메신저 끄기
- 시연 배속은 **×1** 로 시작 (장면 5에서 올립니다)

## 1. 문제 제기 — 30초

**화면:** 랜딩 페이지 `/`

> "레미콘은 비비기 시작하면 90분 안에 타설을 끝내야 합니다. 외기 25도 이상일 때 기준입니다.
> 그런데 앞차와 뒷차 사이가 벌어지면 먼저 친 콘크리트가 굳어버립니다. **콜드조인트**입니다.
> 구조체 강도가 직접 떨어집니다.
>
> 지금 현장은 이걸 전화로 관리합니다. 여러 공장에 일일이 전화해서 물량을 묻고 순서를 조율합니다.
> 저희는 이걸 화면 하나로 옮겼습니다."

스크롤해서 **01 주문 → 02 배분 → 03 추적 → 04 연속 타설** 카드를 보여줍니다.

## 2. 주문 — 조건에 맞는 공장만 남는다 (1분)

**화면:** 노트북, 현장 계정 `/site/order`

**조작:**
1. 사양에서 **보통 / 25mm / 24MPa / 슬럼프 150mm** 확인 (기본값)
2. 총 물량 `60`, 펌프 속도 `40` 입력
3. 지도와 공장 목록을 보여줍니다

> "사양을 고르면 **만들 수 있는 공장만** 남습니다. KS F 4009 표를 그대로 넣었습니다.
> 그리고 제한시간 안에 도착할 수 있는지도 같이 봅니다."

**짚어줄 세 가지** (목록을 위에서 아래로 훑으며):

| 공장 | 화면에 뜨는 것 | 설명할 말 |
| --- | --- | --- |
| 다온레미콘 수원공장 | 빨강 · 출하 여력 없음 | "차량이 전부 나가 있습니다" |
| 새봄레미콘 화성공장 | 빨강 · 출하 중지 | "설비 점검 중입니다" |
| 하늘레미콘 안성공장 | 빨강 · 시간 초과 | "99분 거리라 90분 제한을 못 맞춥니다" |

> "빨간 건 누를 수 없습니다. 전화해서 확인할 필요가 없습니다."

## 3. AI 배분 — 왜 필요한가 (2분, **가장 중요한 장면**)

**화면:** `/site/allocate`

**조작:**
1. **"지시서 6장 A~G 예시로 계산"** 체크박스를 켭니다
2. **AI 배분 계산하기**

**결과 설명:**

> "300㎥를 6분마다 한 대씩, 끊김없이 받아야 합니다. 50대가 필요합니다.
> 주변에 공장이 7곳 있는데 한 곳이 다 대지 못합니다."

결과표를 가리키며:

| 공장 | 이동 | 추천 |
| --- | --- | --- |
| A | 15분 | 5대 |
| B | 20분 | 4대 |
| C | 25분 | 10대 |
| D | 30분 | 5대 |
| E | 35분 | **12대** |
| F | 45분 | **14대** |
| G | 60분 | **0대 — 제외** |

> "G공장은 60분 거리인데 허용 이동시간이 50분이라 아예 뺐습니다.
> 여기서 중요한 건 **E와 F**입니다. 먼 공장인데 **처음부터 섞어 씁니다.**"

아래 **"가까운 공장부터 채우면 어떻게 되나"** 칸을 가리키며:

> "가까운 A, B, C, D부터 순서대로 다 쓰면 어떻게 될까요?
> **39번째 차에서 보낼 공장이 없습니다.** 타설이 끊깁니다.
> 가까운 곳을 먼저 비우면 후반에 먼 공장만 남는데, 그 공장들의 시간당 출하 능력을 합쳐도
> 6분에 한 대를 못 맞추기 때문입니다.
>
> 이게 저희가 최적화를 쓴 이유입니다. 단순히 가까운 순서로는 안 됩니다."

> 💡 이 장면이 발표의 핵심입니다. **39번째에서 끊긴다**는 숫자를 꼭 말하세요.

## 4. 안 될 때는 어떻게 하는가 (1분 30초)

**조작:**
1. **"A~G 예시" 체크를 끕니다** (실제 공장으로 돌아갑니다)
2. 상단 현장이 **서천동**인지 확인
3. 총 물량 `300` 그대로 → **AI 배분 계산하기**

**결과:** 빨간 "배분 불가"

> "실제 데이터로 하면 서천동 현장은 300㎥가 안 됩니다.
> 허용 이동시간 안에 있는 공장들의 차를 다 합쳐도 모자랍니다."

아래 대안 칸을 가리키며:

> "그런데 '안 됩니다'로 끝내지 않습니다.
> **지금 조건에서 몇 ㎥까지 되는지** 계산해서 알려줍니다."

**조작:** **「이 물량으로 바꾸기」** 버튼 클릭 → **AI 배분 계산하기**

> "바로 가능해집니다. 현장이 실제로 알고 싶은 건 '안 된다'가 아니라 '그럼 얼마까지 되냐'입니다."

> ⚠️ 제시되는 물량은 그날 외기온도와 실시간 교통에 따라 달라집니다(222㎥ 부근).
> 숫자를 외워서 말하지 말고 **화면에 뜬 값을 읽으세요.**

## 5. 실시간 공유 (1분 30초)

**조작 (노트북, 현장):** **「N개 공장에 주문 한 번에 보내기」** 클릭

**바로 휴대폰 A를 들어 보여줍니다.**

> "공장 담당자 휴대폰입니다. **아무것도 누르지 않았습니다.**"

주문이 올라와 있는 것을 보여줍니다.

> "현장이 보낸 주문이 실시간으로 도착합니다. 새로고침이 없습니다."

**조작 (휴대폰 A, 레미콘사):**
1. 주문 카드의 판정 태그를 보여줍니다 — "사양 생산 가능 / 출하 가능 / 시간 내 도착"
   > "공장도 따져볼 필요가 없습니다. 받자마자 판정이 돼 있습니다."
2. **수락**
3. **배차** 탭 → 차량 목록에서 **1호차 · 기사 배정됨** 선택 → **출하 지시**

> "출하 지시를 누른 이 순간이 **비비기 시작 시각**입니다. 90분이 여기서부터 흐릅니다."

## 6. 추적 · 지연 예측 · 콜드조인트 경고 (2분)

**화면:** 노트북, `/site/tracking`

**조작:** 시연 배속을 **×60** 으로 올립니다.

> "실제로는 30분 걸릴 운행을 1분으로 줄여서 보겠습니다."

**보여줄 것 (위에서 아래로):**

1. **타설 모니터**
   > "지금 타설 중인 차가 끝나는 시각과 다음 차 도착 예상 사이의 **공백**을 계산합니다.
   > 이 공백이 이어치기 허용 시간에 가까워지면 경고합니다."

2. **지도** — 차량이 실제 도로를 따라 움직입니다
   > "카카오맵입니다. 경로는 실시간 교통을 반영한 추천 경로입니다."

3. **배송 카드의 「도착 예상」**
   > "여기 보시면 **'처음 예상보다 3분 늦음'** 처럼 뜹니다.
   > 출하할 때 잡은 예상 시각을 고정해 두고, 1분마다 다시 계산해서 비교합니다."

4. **「타설 기한」**
   > "비비기 시작부터 90분입니다. 남은 시간이 줄면 색이 바뀝니다."

**조작:** 차가 도착하면 **「타설 완료 확인」**

> ⚠️ 배속을 올린 상태로 오래 두면 여러 차가 한꺼번에 도착합니다.
> 시연이 끝나면 **×1 로 되돌리세요.**

## 8. 예상 질문과 답

| 질문 | 답 |
| --- | --- |
| 공장 데이터는 실제인가요? | **전부 가상입니다.** 공장 위치·출하 능력은 공개 데이터가 아닙니다. 화면에도 그렇게 표기했습니다. |
| 이동시간은 어떻게 구하나요? | 카카오모빌리티 길찾기 API입니다. 실시간 교통이 반영되고, 승용차 기준이라 믹서트럭 보정계수 1.25를 곱합니다. |
| 기사 위치는 어떻게 받나요? | 기사 휴대폰 브라우저의 GPS입니다. **운행 중에만** 수집하고 시작할 때 동의를 받습니다. 화면이 꺼지면 멈추는 한계가 있어, 상용화 단계에서는 차량 단말이 필요합니다. |
| 90분은 어디서 나온 숫자인가요? | 외기 25℃ 이상 90분, 미만 120분입니다. 설정값으로 빼 뒀고 현장이 바꿀 수 있습니다. |
| AI라고 할 수 있나요? | 정수계획 최적화입니다. 학습 모델은 아닙니다. 지연 예측의 학습 보정은 운행 기록이 쌓여야 가능해서 아직 규칙 기반입니다. **과장하지 않고 이렇게 답하세요.** |
| 콘라이브와 뭐가 다른가요? | 콘라이브는 추적과 도착 예측을 합니다. 저희 차별점은 **여러 공장을 묶는 배분**과 **콜드조인트 경고**입니다. |

## 9. 잘못될 때 (Plan B)

| 상황 | 대처 |
| --- | --- |
| 인터넷이 끊김 | 노트북에서 `npm run dev` 로 localhost 시연. 다만 **다기기 공유는 안 됩니다** |
| 지도가 회색으로 뜸 | 카카오 도메인 등록 문제입니다. "대체 지도로 표시 중"이라고 솔직히 말하고 넘어가세요. 기능은 다 됩니다 |
| 실시간이 안 옴 | 휴대폰을 새로고침하세요. Realtime이 끊겼을 뿐 데이터는 들어와 있습니다 |
| 주문이 공장에 안 보임 | 배분 결과에 **그 공장이 포함됐는지** 확인. 가온레미콘이 빠졌으면 다른 현장으로 다시 계산 |
| 기사 화면이 비어 있음 | 기사가 **차량을 맡았는지**, 공장이 **그 차로 배차했는지** 확인 |
| AI 배분이 계속 불가 | 외기온도를 손으로 `20` 으로 낮추면 제한이 120분이 되어 대부분 가능해집니다 |

## 11. 역할 분담 (발표자 3명 기준)

| 사람 | 맡는 것 |
| --- | --- |
| 발표자 | 말하기 + 노트북 조작 (장면 1~4, 6~7) |
| 보조 1 | 휴대폰 A(레미콘사) 조작 — 장면 5의 수락·배차 |

보조는 **발표자가 신호를 줄 때까지 아무것도 누르지 않습니다.** 미리 누르면 실시간으로 도착하는
장면이 죽습니다.
